# Supplier portal API (starter lab)

A gentle first CyberCTF lab: no vulnerability. You learn to read a small REST
API's docs and make an authenticated request.

**Task:** report the amount of invoice `INV-20507` from the portal API.

## Run it

The lab is described once in [`isoloom.yml`](isoloom.yml) ([Isoloom](https://www.isoloom.com)):
containers or one VM per machine, on this machine, a server or a cloud. With Docker:

```bash
docker compose -f .isoloom/docker/compose.yml up -d --build --wait
```

With VMs (VirtualBox, VMware, Parallels, libvirt): `cd .isoloom/vagrant && vagrant up`.
After changing `isoloom.yml`, run `isoloom generate` and commit `.isoloom/`.

Open http://localhost for the API docs, then:

```bash
curl -H "X-Portal-Key: vendor-demo-key" http://localhost/api/invoices/INV-20507
```

The `amount` field is your evidence. Without the CyberCTF launcher the lab uses
its public development value; launched from CyberCTF you get your own value.

## Layout
- `build/web/` , Flask API (`src/app.py`) + Dockerfile
- `isoloom.yml` , the lab: machines, network, services, inputs, checks
- `build/database/` , MySQL image (schema, seed) and the evidence claim and placement
- `provision/` , the same machines as Debian VMs
- `build/check/check.sh` , the lab is still solvable (run from the player's side)
- `.isoloom/` , generated by `isoloom generate` (Compose, Vagrant, Terraform), don't edit
- `tests/` , pytest suite (runs against `.isoloom/docker/compose.yml`)
